mimir

A statistically rigorous experiment harness for LLMs and other stochastic systems.

Eric Xu·August 2026

Python·Apache-2.0·v0.1.0

GitHub

Abstract

In Norse mythology, Mimir guarded the well of wisdom beneath the world tree. Odin gave up an eye for a single drink from it. Real knowledge comes at a cost, and the same is true for any stochastic system where you can't just eyeball a few outputs and know which variant is better: an LLM prompt, a randomized algorithm, a noisy benchmark, a policy.

mimir is an experiment harness for those systems. You describe an experiment in a YAML file (a few variants, a dataset, how many samples). mimir runs it and then tells you whether the difference you see is real: paired bootstrap confidence intervals, a sign-flip p-value, a power estimate, multiple-comparison correction when there are more than two arms, and a report card on the LLM judge itself.

Why

The failure mode this is built for will be familiar to anyone who has tuned prompts. You change a system prompt, rerun the eval, the score moves two points, and you ship it. With sampled outputs, the noise between runs is often larger than the effect you're chasing, and if an LLM is grading the outputs it brings its own position and length biases along for the ride.

mimir makes you say up front what you expect to happen, then gives you the statistics to know whether it did.

How it works

Runs append to a SQLite file in the current directory. Responses are cached by content, so re-running a spec only executes what changed, and analysis is a pure read of the store.

Comparisons are paired per item: for every dataset item, the score of one variant minus the score of the other. The confidence interval comes from a bootstrap over items (10,000 resamples) and the p-value from a sign-flip permutation test. Up to 16 items the sign-flip is exhaustive, all 65,536 patterns, which happens to be the small-n regime where Monte Carlo error would be worst. The report also estimates how many more items you'd need to reach 80% power, and splits the variance into item effect versus replicate noise, which answers the practical question of whether to collect more items or more samples per item. Multi-arm runs get Holm or Benjamini-Hochberg correction over every pairwise comparison.

If a spec declares a hypothesis and an analysis plan, mimir prints a sha256 of the hypothesis, plan and design when the run starts. That's the preregistration. You can show afterwards that the analysis wasn't picked after looking at the data.

audit-judge turns the same machinery on the judge. It reports position bias (does the judge prefer whichever answer it sees first) and length bias (does it prefer longer answers), and it can compare two judge runs against each other.

Beyond LLMs

A condition doesn't have to be an LLM call. A subprocess condition is any program that takes a seed and prints a score, so the same harness compares seeded algorithms. The bundled non-LLM example pre-registers the hypothesis that simulated annealing beats random-restart hill climbing on seeded knapsack instances, runs 192 samples with no API key, and analyzes the result with the same paired bootstrap.

$ uv run mimir run examples/non_llm/experiment.yaml --db knap.db
run 20260804-021035-6678 complete
samples: 192 (0 errors) | judgments: 192 (0 errors)
preregistered: 717a237bb2f1...   <- sha256 of the hypothesis + analysis plan + design

$ uv run mimir analyze 20260804-021035-6678 --db knap.db

CLI

CommandWhat it does
mimir run SPEC [--db PATH] [--mock]run the experiment and its judge or scorer, if configured; prints the preregistration hash for planned specs
mimir analyze RUN_ID [--html] [--correction bh|holm]paired-bootstrap stats report, optionally as a self-contained HTML file
mimir audit-judge RUN_ID [--compare RUN_ID]judge reliability report card

Exit codes: 0 on success, 1 for domain errors (bad spec, missing files, missing API key, a failed run), 2 for usage errors. Reports go to stdout; warnings go to stderr.

Status

Version 0.1.0. Not on PyPI yet, so install from source with uv. Python 3.12 or newer. Four runtime dependencies: httpx, pydantic, pyyaml and numpy.

git clone https://github.com/ericxu88/mimir.git && cd mimir
uv sync
uv run mimir run examples/quickstart.yaml --mock     # offline, canned client
uv run mimir run examples/judged.yaml                # needs ANTHROPIC_API_KEY
uv run mimir analyze <run-id> --html
