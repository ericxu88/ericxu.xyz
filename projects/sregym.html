SREGym

A procedurally generated incident-response environment for LLM agents.

Eric Xu·August 2026

GitHub Environments Hub

00Abstract

Each episode builds a small production stack on disk: a FastAPI service, SQLite databases, a git repo with history, nginx, systemd and cron config, and hours of logs and metrics that agree with each other. A fault gets injected, the agent gets paged, and a deterministic verifier checks whether it fixed the root cause without breaking anything else. No LLM judge.

10 fault templates, two-fault compositions, three difficulty levels, 8 stack identities. Seeds are reproducible. Ships with Anthropic and OpenAI-compatible adapters, a scripted solver, a sweep runner, and a verifiers taskset on Prime Intellect's Environments Hub.

01An episode

The world is real, not mocked

The agent gets the page, a support note, a system prompt describing the host and the tools, and a step budget. The service actually runs: a uvicorn subprocess with synthetic traffic at about 1.5 requests per second, a metrics scrape every 10 seconds, and a real cron daemon. Config changes only take effect after a restart, which is where many episodes fail.

Seven tools

ToolWhat it does
read_logspaginated log reads with grep, time range, tail
query_metricsper-minute request, latency and error series
read_file / edit_filenumbered lines; exact-string replace, returns a diff
run_shellallow-listed: inspection, read-only git and sqlite3, curl to localhost
restart_servicerestarts the service, re-reads .env
resolve_incidentends the episode with a postmortem

The scripted solver proves every seed is solvable

$ sregym run --seed 42 --agent scripted
[step 3]  read_logs(app.log, grep='5\d\d')        -> 1688 matching lines
[step 7]  run_shell('git show HEAD')               -> -DATABASE_URL  +DATABSAE_URL
[step 10] edit_file('.env', DATABSAE_URL -> DATABASE_URL)
[step 11] restart_service()                        -> GET /health 200
[step 16] resolve_incident(...)                    reward=1.00

It is a solvability oracle, not a benchmark. It scores 1.0 on every seed, and its mask, workaround, noop and sloppy modes exercise the failure cases the verifier has to tell apart.

Ten templates, each with a deliberate evidence trail

Two faults at once, and eight stack identities

Composition puts two faults in one world with one page; reward there is all or nothing. Every world also draws one of 8 stack identities (service name, package, database files, routes), so there is no single playbook to memorize.

03Verifier

Three checks, no LLM judge

The symptom is gone: health, a synthetic checkout and reads all succeed. The root cause is fixed: the broken thing is correct again, app code is unchanged, nothing was renamed to match a typo. Nothing else broke: file hashes, database rows, logs and git history are intact, and no destructive command ran.

Partial credit is deliberate

1.0 if all three pass, otherwise 0.3 for the symptom plus 0.7 for the root cause, halved on collateral damage. Restart only scores 0. A hardcoded workaround scores 0.15. The right fix without a restart scores 0.7.

The step budget is the main difficulty lever

env_var_typo goes 100% at 30 steps, 95% at 12, 65% at 10, 15% at 8. Prompt verbosity made no difference. Opus 5 also went 20/20 at 30 steps.

When every run fails the same way, suspect the rubric

bad_dependency_pin first scored 0/20: every run fixed forward instead of rolling back. The model was right. The verifier now accepts either coherent end state, and sregym rescore re-judged the saved runs without re-running any models.

Scope is harder than time pressure

Two faults at once drops to 30%, and every failure is never_found. Stack variation didn't change difficulty: on identical worlds the run-to-run swing was larger than any identity effect.

05Quick start

uv pip install -e ".[dev]"
sregym run --seed 42 --agent scripted          # offline, ~4s
sregym sweep --seeds 1-200 --model claude-sonnet-5 --out sweeps/run1
prime env install ericxu88/sregym-env          # verifiers taskset

Without Docker the sandbox is an allow-list plus path confinement. Don't point an untrusted agent at a host you care about.
